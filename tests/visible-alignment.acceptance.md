# 可见需求对齐：行为验收

这是维护者的聚焦验收材料，不是 Skill 的运行步骤。不要把本文件、参考答案或版本评判喂给被测模型。

使用 fixtures/visible-alignment.json 中的原始请求和来源，在隔离目录实际运行待测 Skill。只给被测模型用户输入、来源、待测 Skill 和必要的读写边界；各会话的材料和输出分开。需要第二轮时，先保留真实提问，再给对应用户回答，不预先透露回答。恢复测试只给恢复提示和历史定位线索，历史中保存此前的实际问答。无真实上下文压缩时应标为受控恢复。

保存各轮实际聊天、生成的 Markdown、来源、工具读写记录、Skill 内容哈希、模型与推理设置。比較版本时使用相同输入和设置；新增迁移样例应在版本冻结后运行，不因为看到失败而删除原始结果。测试输出只进隔离目录，不连接业务系统、发送消息、自动调用 Clinic 或修改真实资料。

评审实际含义与问答顺序：

| 场景 | 观察重点 |
| --- | --- |
| 已有候选逐项验证 | 保留每个候选的验证责任及来源中重要约束，不偷换成开放探索或先选赢家。任务已明确时不重复问目标。 |
| 真实目标歧义 | 聊天展示当前理解和会影响研究的合理差别；问能区分意图的问题，不能靠假设或同时研究全部解释回避。 |
| 回答改变目标 | 第二轮正文真正更新对象、范围与成功表现，清除冲突的旧解释；不能只在末尾追加新答案。 |
| 多个意图、偏好未定 | 保留并存目标；用具体差异帮助表达，不强制单选、擅自排序或虚构权重。用户允许留给研究的取舍不阻断。 |
| 已答与上下文恢复 | 复用有效答案，恢复当前请求，处理仍未完成的独立文字；不相信过时摘要而重复问或交旧报告。 |
| 聊天与文件 | 只看聊天也能知道研究什么、候选责任、护栏、授权及事实强度；文件正文相同，来源附件没有新增实质要求。 |
| 新领域迁移 | 更换对象和名词后仍满足上述含义，不依赖某个技术例句。 |

同名历史文件应保留，实际标题、链接和交接路径一致。完整正文可作文本包含检查辅助核对，但来源附录、链接规范化或格式差异仍需按语义复核；不要把字符一致当成目标正确的证明。

静态合同测试和 quick_validate 只证明规则与包装。受控样例、已安装文件、原生宿主调用和用户实际体验分别报告。基线若也通过应如实保留；少量样例不能估计故障率或证明跨宿主稳定性。不为本项维护建立固定 Agent 流程或生产状态机制。
